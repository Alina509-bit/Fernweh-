03Zwei wichtige Entscheidungen (ADR)

Ich habe X statt Y gewählt, weil …

ADR-003 · Anmeldung

Server-Session im HttpOnly-Cookie

VerworfenJWT im localStorage + Authorization-Header
WeilToken im localStorage ist per XSS lesbar; JWT kann vor Ablauf nicht widerrufen werden. Session: Logout wirkt sofort, Cookie für JS unsichtbar.
KonsequenzServer speichert Sessions (nur SHA-256 des Tokens). CSRF beachten → SameSite=Lax, JSON-only, CORS nur :5173.
PasswörterPBKDF2-SHA256, 600 000 Iterationen, Salt pro Nutzer.
ADR-002 · Persistenz

JSON-Dateien hinter einem Interface

VerworfenSQLite / Deno KV
Weil3 kleine Sammlungen, wenige Nutzer – Architektur bleibt sichtbar, keine Zusatz-Infrastruktur. Schreiben atomar und serialisiert.
KonsequenzKeine Transaktionen/Indizes, skaliert nicht. Austausch betrifft nur JsonFileCollection – Services und API bleiben gleich.
DatentrennunguserId nur aus der Session; fremde ID → 404.

05Fazit

Klein, vollständig, entkoppelt, begründbar.

Abweichungen vom Entwurf

  • Benutzerkonten mit Login, Session-Cookie und Datentrennung – vorher eine gemeinsame Liste.
  • Feld imageUrl (nur HTTPS) für die Karten-Darstellung.
  • Kein Vue Router / Pinia – Composables reichen für eine Seite.

Was ich anders machen würde

  • SQLite statt JSON-Dateien (Transaktionen, Indizes, Filtern in der DB).
  • Datenmodell und API zuerst als OpenAPI festlegen.
  • Frühzeitig Frontend-Tests (Vitest) ergänzen.

Größte Schwäche

  • Kein Rate-Limiting beim Login – Brute-Force wird nur durch die PBKDF2-Kosten gebremst.
  • JSON-Persistenz skaliert nicht für viele Nutzer.
  • Kein Passwort-Reset, Bilder nur als externe URL.
